# 美國兩個月旅遊知識庫 — LLM 操作指南

## 概覽

這是一個針對美國兩個月旅遊規劃的知識庫，基於 Karpathy 的 llm-wiki 模式建立。
你的工作是：丟入資料（城市、景點、美食、交通）、提問、決定方向。
LLM 的工作是：整理、交叉引用、建立頁面、維護一致性。

---

## 目錄結構

```
/
├── AGENTS.md              ← 本文件：LLM 操作指南（Schema）
├── index.md               ← 所有 wiki 頁面的目錄索引
├── log.md                 ← 操作日誌（append-only）
│
├── raw/                   ← 原始資料來源（LLM 只讀，不修改）
│   ├── articles/          ← 網路文章、攻略、部落格
│   ├── notes/             ← 個人筆記、想法
│   └── assets/            ← 圖片、附件
│
└── wiki/                  ← LLM 生成與維護的知識頁面
    ├── itinerary.md       ← 完整行程總表（城市順序、天數分配）
    ├── cities/            ← 每個城市一個頁面
    ├── themes/            ← 主題頁面（美食、文化、戶外等）
    ├── planning/          ← 規劃工具（預算、打包清單等）
    ├── logistics/         ← 實務資訊（城市間交通、住宿、網路）
    └── insights/          ← 分析與比較（LLM 生成的洞察）
```

## 搜尋功能（qmd 整合）

本知識庫整合了 [qmd](https://github.com/tobi/qmd) 本地搜尋引擎，支援：
- **關鍵字搜尋**（BM25）：`qmd search "金門大橋"`
- **語意搜尋**（向量）：`qmd vsearch "舊金山有什麼免費景點"`
- **混合搜尋 + 重排序**（最佳品質）：`qmd query "拉斯維加斯免費景點"`

### 初始設定（首次使用）

```bash
# 安裝 qmd
npm install -g @tobilu/qmd

# 將 wiki 和 raw 目錄加入 collection
qmd collection add ./wiki --name wiki
qmd collection add ./raw --name raw

# 加入 context 說明（幫助搜尋更準確）
qmd context add qmd://wiki "美國旅遊知識庫，包含城市攻略、景點、美食、交通"
qmd context add qmd://wiki/cities "各城市詳細攻略頁面"
qmd context add qmd://wiki/insights "深度分析與比較（羚羊谷、景點門票等）"
qmd context add qmd://wiki/logistics "交通、住宿、網路等實務資訊"
qmd context add qmd://raw/articles "原始攻略文章來源"

# 中文支援（建議使用 Qwen3 多語言模型）
export QMD_EMBED_MODEL="hf:Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf"

# 生成向量嵌入
qmd embed
```

### 日常使用

```bash
# 新增資料後更新索引
qmd update

# 搜尋範例
qmd query "舊金山免費景點"
qmd query "拉斯維加斯住宿推薦"
qmd query "優勝美地旺季預約"
qmd search "門票" -c wiki          # 只搜尋 wiki
qmd vsearch "沙漠度假" -c wiki     # 語意搜尋
```

### MCP Server（讓 LLM 直接搜尋）

```bash
# 啟動 MCP Server（背景執行）
qmd mcp --http --daemon

# 停止
qmd mcp stop
```

在 Kiro 的 `.kiro/settings/mcp.json` 加入：

```json
{
  "mcpServers": {
    "qmd": {
      "command": "qmd",
      "args": ["mcp"]
    }
  }
}
```

啟用後，LLM 可以直接呼叫 `query`、`get`、`multi_get` 工具搜尋知識庫，不需要每次手動讀取檔案。

## 頁面格式規範

### 所有 wiki 頁面的 YAML frontmatter

```yaml
---
title: 頁面標題
category: cities | themes | planning | logistics | insights | itinerary
tags: [標籤1, 標籤2]
state: 州名（cities 頁面專用）
created: YYYY-MM-DD
updated: YYYY-MM-DD
source_count: 0
---
```

### 城市頁面（cities/）

每個城市頁面應包含：
- **概覽**：城市簡介、所在州、最佳停留天數建議
- **必訪景點**：列表 + 簡短說明 + 費用
- **美食推薦**：當地特色料理、推薦餐廳
- **城市內交通**：地鐵、公車、步行、Uber 等
- **住宿區域建議**：哪個區域最適合住
- **實用資訊**：停車、小費文化、注意事項
- **相關頁面**：連結到主題頁面、鄰近城市
- **資料來源**：引用的 raw/ 文件

## 操作流程

### 1. 新增資料來源（Ingest）

1. 將原始資料存入 `raw/` 對應子目錄
2. 閱讀並整理重點
3. 在 `wiki/` 建立或更新相關頁面
4. 更新 `index.md`
5. 在 `log.md` 新增一筆記錄
6. **執行 `qmd update` 更新搜尋索引**

### 2. 回答問題（Query）

1. **優先使用 qmd 搜尋**（若已設定）：`qmd query "問題關鍵字"`
2. 或讀取 `index.md` 找出相關頁面，再讀取 wiki 頁面
3. 綜合回答，附上頁面引用
4. 若答案有價值，整理成 `insights/` 頁面
5. 在 `log.md` 記錄此次查詢

### 3. 健康檢查（Lint）

定期執行，檢查：
- 斷鏈與編碼破壞
- 矛盾或錯誤的舊資訊（票價、開放時間、天數）
- 行程總表與城市頁面的天數是否一致
- 孤立頁面（無內部連結指向）
- raw/ 未整合文章
- 城市頁面完整度
- 詳細清單見「Lint 健康檢查完整指南」

## Lint 健康檢查完整指南

### 何時執行

建議在以下情況執行 Lint：
- 新增 3–4 個城市頁面後
- 大量更新頁面後
- 發現資訊不一致時
- 每隔一段時間定期執行

### 執行方式

直接告訴 LLM：「幫我執行 Lint 健康檢查」或「Lint 健康檢查」

### 檢查項目清單

#### 1. 斷鏈檢查（最重要）
搜尋所有已刪除頁面的殘留連結：
- `[[wiki/overview]]` — 已刪除，應改為 `[[index]]`
- `[[wiki/themes/親子旅遊]]` — 已刪除
- `[[wiki/themes/獨旅]]` — 已刪除
- `[[wiki/logistics/簽證指南]]` — 已刪除
- `[[wiki/logistics/旅遊保險]]` — 已刪除
- `[[wiki/planning/行程規劃指南]]` — 已刪除
- `[[wiki/planning/行程模板-3天]]` — 已刪除
- `[[wiki/planning/行程模板-7天]]` — 已刪除

#### 2. 編碼檢查
確認所有頁面中文是否正常（無亂碼如 `?��?`）

#### 3. 連結一致性
- `index.md` 的城市列表是否與實際 `wiki/cities/` 目錄一致
- `wiki/itinerary.md` 的城市連結是否都指向存在的頁面
- 各城市頁面底部「相關頁面」是否有效

#### 4. 內容一致性
- `itinerary.md` 的天數與住宿策略是否一致
- 各城市頁面的「建議停留天數」是否與行程總表一致
- 城市間交通路線表是否完整

#### 5. 孤立頁面
確認每個 wiki 頁面都有被至少一個其他頁面引用

#### 6. 待建立頁面
確認 `_(待建立)_` 的頁面是否仍在計畫中

#### 7. 矛盾與錯誤資訊
跨頁面比對同一景點/城市的關鍵數據，找出不一致：
- **票價矛盾**：同一景點在不同頁面（城市頁、門票總覽、insights）的票價是否一致
- **開放時間矛盾**：同一景點在不同頁面的開放時間是否一致
- **天數建議矛盾**：城市頁面的「建議停留天數」與 `itinerary.md` 的實際安排是否衝突
- **交通資訊矛盾**：同一路線的車程時間、票價在不同頁面是否一致
- **已知錯誤**：與 raw/ 來源文章明顯不符的資訊（例如票價已更新但 wiki 未同步）

#### 8. 來源覆蓋率
- wiki 頁面中是否有「無來源支撐」的重要說法（尤其是票價、開放時間等具體數字）
- `raw/articles/` 中是否有已存在但尚未 ingest 進 wiki 的文章
  - 做法：列出 `raw/articles/` 所有檔案，對照各城市頁面的 `source_count` 和來源引用

#### 9. 時效性
- 票價、開放時間是否標注資料年份或來源日期
- 季節性資訊（旺季預約、特殊活動）是否仍在有效期內
- 2026 特殊事件提醒（超級盃、世界盃等）是否已過期或仍適用

#### 10. 行程合理性
- **天數加總**：`itinerary.md` 的總天數是否符合實際出發/回程日期
- **地理合理性**：相鄰兩天的城市之間車程是否合理，有無不必要的跳躍移動
- **預約提醒**：需提前預約的景點（惡魔島、羚羊谷、優勝美地旺季）是否在行程中標注

#### 11. 城市頁面完整度
確認每個城市頁面都包含以下五個核心區塊：
- [ ] 概覽（所在州、建議天數、最佳季節）
- [ ] 必訪景點（含費用）
- [ ] 美食推薦
- [ ] 城市內交通
- [ ] 住宿區域建議

### 修復優先順序

| 優先級 | 問題類型 | 說明 |
|--------|----------|------|
| 🔴 高 | 斷鏈 | 連結指向不存在的頁面，立即修復 |
| 🔴 高 | 編碼破壞 | 中文亂碼，立即重寫頁面 |
| 🔴 高 | 矛盾資訊 | 同一景點票價/時間在不同頁面不一致，以最新來源為準修復 |
| 🟡 中 | 內容不一致 | 天數、交通資訊矛盾，盡快修復 |
| 🟡 中 | 缺少交叉引用 | 相關頁面未連結，補充 |
| 🟡 中 | 未整合文章 | raw/ 有新文章尚未 ingest，安排處理 |
| 🟡 中 | 行程不合理 | 天數加總錯誤或地理跳躍，調整 itinerary |
| 🟢 低 | 孤立頁面 | 無人引用，補充連結 |
| 🟢 低 | 時效性問題 | 票價未標年份、過期活動提醒，補充說明 |
| 🟢 低 | 頁面不完整 | 缺少核心區塊，補充內容 |

### Lint 記錄格式

```
發現並修復以下問題：

2. ...

無其他問題：
✅ 無斷鏈
✅ 無編碼破壞
✅ 無矛盾資訊
✅ 所有連結正確
✅ 無未整合文章
✅ 行程天數合理
✅ 城市頁面完整
```

## 命名規範

- 城市頁面：`cities/城市名稱.md`（英文，例如 `cities/San-Francisco.md`）
- 主題頁面：`themes/主題名稱.md`（例如 `themes/美食.md`）
- 規劃頁面：`planning/工具名稱.md`
- 洞察頁面：`insights/主題.md`

---

## 交叉引用規則

- 使用 Obsidian 內部連結格式：`[[頁面名稱]]` 或 `[[頁面名稱|顯示文字]]`
- 每個頁面底部必須有「相關頁面」區塊
- 城市頁面應連結到相關主題頁面
- `itinerary.md` 應連結到所有城市頁面
